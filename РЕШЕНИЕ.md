## 1. Задание

Нужно написать на Windows Forms простой графический редактор, похожий на Paint. В нём есть меню «Файл» (Создать, Открыть, Сохранить, Сохранить как, Выход), панель инструментов (карандаш, ластик, отрезок, прямоугольник, эллипс/окружность, заливка, выделение), выбор цвета контура и заливки и выбор толщины линии. **Редактор должен создавать, открывать и сохранять картинки минимум в двух форматах (BMP и JPEG), поддерживать отмену и повтор (Undo/Redo), копирование, вырезание и вставку выделенной области, а также выводить графику с двойной буферизацией.**

### Почему сделано именно так

- **Рисуем в `Bitmap`, а не прямо на форме.** Если рисовать на экране через `CreateGraphics()`, изображение пропадёт, когда окно свернут или перекроют. В `Bitmap` картинка хранится в памяти и не теряется. Её же можно сохранить в файл, скопировать для Undo и положить в буфер обмена.
- **Холст — это `PictureBox` внутри `Panel` с `AutoScroll = true`.** У `PictureBox` двойная буферизация включена «из коробки». Панель даёт полосы прокрутки, если открытая картинка больше окна.
- **Текущий инструмент хранится как ссылка на нажатую кнопку** (`ToolStripButton currentTool`), без отдельного `enum`. Проверка читается прямо: `currentTool == btnFill`. Все семь кнопок используют один обработчик `toolButton_Click`.
- **Ластик — это закраска цветом фона**, а не «прозрачность». Картинка BMP/JPEG не хранит прозрачность, а фон холста белый, поэтому стереть = закрасить белым. Цвет фона вынесен в поле `backgroundColor`: его же используют «Создать» (`g.Clear`) и «Вырезать», и все три места согласованы.
- **Ластик ставит квадраты в каждую точку пути**, а не рисует толстую линию. Квадрат — привычная форма ластика (как в Paint), а толстая линия с квадратными концами на диагонали дала бы повёрнутые углы. При быстром движении мыши события `MouseMove` приходят редко, поэтому путь между двумя событиями заполняется квадратами по шагам (без пропусков).
- **Undo хранит копии картинки целиком**, а не список команд. Так проще всего: любое действие (карандаш, заливка, вставка) отменяется одинаково. Минус — расход памяти (см. вопросы).
- **Заливка работает через `LockBits` и массив `int[]`**, а не через `GetPixel/SetPixel`. `GetPixel` очень медленный: заливка всей картинки 800×500 заняла бы заметное время. С массивом она проходит примерно за 50 мс (замерено).

## 4. Как работает основная логика

### Состояние программы (поля `Form1`)

| Поле | Назначение |
|---|---|
| `Bitmap bmp` | Текущая картинка, в неё рисуют все инструменты |
| `Stack<Bitmap> undoStack` | Копии картинки **до** каждого изменения |
| `Stack<Bitmap> redoStack` | Отменённые состояния для «Повторить» |
| `string currentFile` | Путь к открытому или сохранённому файлу. `null` — картинка ещё не сохранялась |
| `ToolStripButton currentTool` | Кнопка выбранного инструмента |
| `Color lineColor`, `fillColor` | Цвет контура (по умолчанию чёрный) и цвет заливки (по умолчанию жёлтый) |
| `Color backgroundColor` | Цвет фона (белый): им заполняется новая картинка, стирает ластик и закрашивается вырезанная область |
| `bool drawing` | Зажата ли сейчас левая кнопка мыши |
| `Point startPoint` | Точка, где нажали кнопку мыши (первый угол фигуры) |
| `Point lastPoint` | Предыдущая точка карандаша или ластика |
| `Point endPoint` | Текущая точка мыши при рисовании фигуры (второй угол) |
| `Rectangle selection` | Выделенная область. `Rectangle.Empty` означает, что ничего не выделено |

### Группы действий

- **Мышь** (`canvas_MouseDown/Move/Up`) рисует выбранным инструментом.
- **Отрисовка** (`canvas_Paint`) выводит на экран `bmp`, затем «резиновую» фигуру, рамку выделения и рамку ластика под курсором.
- **Панель инструментов** переключает инструмент, выбирает цвета; толщина читается из `cmbWidth` в `CreatePen()`.
- **Меню «Файл»** создаёт, открывает и сохраняет картинку.
- **Меню «Правка»** отвечает за Undo/Redo и буфер обмена.

### Ключевые алгоритмы

**1. «Резиновая» фигура.** Во время перетаскивания фигура рисуется только на экране (в `Paint`), в `bmp` её ещё нет. Поэтому при каждом движении мыши старая «резиновая» фигура сама исчезает: `Paint` каждый раз заново выводит чистый `bmp`. В `bmp` фигура попадает один раз, в `MouseUp`.

Пример: прямоугольник от (100,100) до (200,200). Во время перетаскивания пиксель (150,100) в `bmp` белый (`ffffffff`). После `MouseUp` он чёрный (`ff000000`), а в `undoStack` лежит 1 копия.

**2. Прямоугольник по двум точкам** (`MakeRect`). Мышь можно тянуть в любую сторону, поэтому левый верхний угол равен минимуму координат, а размер — модулю разности. Из точек (200,50) и (100,150) получится `Rectangle(100, 50, 100, 100)`.

**3. Ластик** (`Erase(a, b)`). Число шагов — наибольшая из разностей по X и по Y, то есть сколько пикселей между точками по «длинной» оси. На каждом шаге `i` точка берётся пропорционально: `x = a.X + (b.X - a.X) * i / steps`, и в неё ставится белый квадрат `EraserRect` с центром в этой точке. Пример: толщина 2 → квадрат 8×8. Мышь прыгнула из (100,100) в (110,100): `steps = 10`, ставятся 11 квадратов с центрами (100,100), (101,100) … (110,100), стёрта полоса от x = 96 до x = 113 и от y = 96 до y = 103. Если `a == b` (просто щелчок), `steps = 0`, и ставится один квадрат.

**4. Заливка** (`FloodFill`). Берём цвет пикселя под курсором (`oldColor`). Кладём точку в стек. Пока стек не пуст: достаём точку. Если она за границей или её цвет не `oldColor`, пропускаем её. Иначе красим в новый цвет и кладём в стек четырёх соседей. Пример: клик внутри чёрного прямоугольника из примера выше. Внутренняя точка (150,150) становится жёлтой (`ffffff00`), а точка снаружи (50,50) остаётся белой: чёрная рамка не пускает заливку наружу.

## 5. Главное требование задания

Главное — рисование инструментами на `Bitmap` с двойной буферизацией, Undo/Redo, файлы и буфер обмена.

### Рисование и двойная буферизация

```csharp
private void canvas_Paint(object sender, PaintEventArgs e)
{
    e.Graphics.DrawImage(bmp, 0, 0, bmp.Width, bmp.Height);   // 1) сама картинка
    if (drawing && IsShapeTool())
        DrawShape(e.Graphics, startPoint, endPoint);          // 2) «резиновая» фигура
    if (selection.Width > 0 && selection.Height > 0)
        ... e.Graphics.DrawRectangle(pen, selection);         // 3) рамка выделения
}
```

Буферов получается два:
1. `bmp` — внеэкранная картинка, в которой хранится результат;
2. буфер `PictureBox`. Всё, что рисуется в `Paint` (картинка + фигура + рамка), сначала собирается в памяти и выводится на экран одной операцией. Промежуточного состояния (например, картинка уже есть, а фигуры ещё нет) пользователь не видит, поэтому нет мерцания.

Обработчики мыши на экран не рисуют. Они меняют данные и вызывают `canvas.Invalidate()`, то есть просят Windows перерисовать холст через `Paint`.

### Undo/Redo

```csharp
private void SaveUndo()            // вызывается ПЕРЕД каждым изменением bmp
{
    undoStack.Push((Bitmap)bmp.Clone());
    redoStack.Clear();
}
private void undoMenuItem_Click(...)
{
    if (undoStack.Count == 0) return;
    redoStack.Push(bmp);
    SetBitmap(undoStack.Pop());
}
```

| Ситуация | Где проверяется | Что происходит |
|---|---|---|
| Нарисовали фигуру / стёрли ластиком / залили / вставили / вырезали | `SaveUndo()` перед изменением | Копия «до» кладётся в `undoStack`, `redoStack` очищается |
| Ctrl+Z при пустой истории | `undoMenuItem_Click`: `undoStack.Count == 0` | Ничего не происходит |
| Ctrl+Y после нового действия | `SaveUndo()` очистил `redoStack` | Повторять нечего, ничего не происходит |
| «Создать» или «Открыть» | `NewImage` / `openMenuItem_Click` | Оба стека очищаются, история начинается заново |
| Копировать / вырезать без выделения | `selection.Width == 0 \|\| selection.Height == 0` | Ничего не происходит |
| Вставить, когда в буфере не картинка | `Clipboard.ContainsImage()` | Ничего не происходит |
| Ластик у края картинки | `FillRectangle` в `Erase` | Часть квадрата за границей просто не рисуется, ошибки нет |
| Мышь с ластиком ушла с холста | `canvas_MouseLeave` → `Paint`: `ClientRectangle.Contains(mouse)` | Рамка ластика исчезает |
| Выделение тянут за край картинки | `Rectangle.Intersect(..., картинка)` в `MouseMove` | Выделение обрезается по границе картинки |
| Открыли файл, который не является картинкой | `try/catch` в `openMenuItem_Click` | Появляется сообщение «Не удалось открыть файл: …», текущая картинка не меняется |
| «Сохранить» у новой картинки | `currentFile == null` | Открывается «Сохранить как» |
| Имя файла с расширением `.jpg`/`.jpeg` | `SaveToFile` | Файл сохраняется в JPEG, с любым другим расширением — в BMP |

## 7. Возможные вопросы на защите

1. **Где двойная буферизация?** Рисуем во внеэкранный `Bitmap bmp`. На экран выводим в `Paint` элемента `PictureBox`, а у `PictureBox` в конструкторе включён стиль `ControlStyles.OptimizedDoubleBuffer`. Поэтому содержимое `Paint` сначала собирается в памяти и выводится целиком, без мерцания.
2. **Почему нельзя рисовать через `canvas.CreateGraphics()`?** Нарисованное пропадёт при первой же перерисовке окна (свернули, перекрыли) и будет мерцать. Кроме того, его нельзя сохранить в файл.
3. **Почему прямоугольник рисуется в `bmp` в `MouseUp`, а карандаш сразу в `MouseMove`?** Карандаш оставляет след, и каждый кусочек постоянный. Фигура до отпускания мыши ещё меняется. Если рисовать её в `bmp` при каждом движении, останутся все промежуточные прямоугольники.
4. **Зачем `SaveUndo()` вызывается до изменения, а не после?** В стек кладётся состояние, **к которому** надо вернуться. У карандаша `SaveUndo()` стоит в `MouseDown`: весь штрих от нажатия до отпускания отменяется одним Ctrl+Z.
5. **Почему после нового действия очищается `redoStack`?** История пошла по другой ветке. Повторять отменённое поверх новых изменений было бы бессмысленно, так же ведут себя все редакторы.
6. **Какой недостаток у такого Undo?** Каждый шаг — полная копия картинки: 800×500×4 байта ≈ 1,6 МБ. Сотня действий займёт ~160 МБ. Можно ограничить глубину истории или хранить только изменённый участок.
7. **Как работает заливка? Почему стек, а не рекурсия?** Алгоритм flood fill описан в разделе 4. Рекурсия на большой области (сотни тысяч пикселей) переполнит стек вызовов (`StackOverflowException`). Явный `Stack<Point>` хранится в куче, и ему это не грозит.
8. **Как работает ластик? Почему он закрашивает белым, а не делает пиксели прозрачными?** Ластик ставит квадраты цветом фона в каждую точку пути мыши (раздел 4). Прозрачность бессмысленна: холст белый, а BMP (24 бита) и JPEG прозрачность не хранят. Цвет фона хранится в одном поле `backgroundColor`, его используют «Создать», «Вырезать» и ластик. Рамка под курсором нужна, потому что белое на белом не видно.
9. **Зачем `LockBits` и `Marshal.Copy`?** `GetPixel/SetPixel` каждый раз блокируют картинку и работают медленно. Здесь картинка один раз копируется в массив `int[]`, заливка идёт по массиву, результат копируется обратно.
10. **Почему при открытии делается `new Bitmap(img)`, а `img` сразу освобождается?** `Image.FromFile` держит файл открытым, пока жив объект. Без копии не получилось бы сохранить картинку в тот же файл. Кроме того, копия всегда получает формат 32bppArgb, а он нужен `Graphics.FromImage` (с индексированной палитрой он не работает) и `FloodFill`.
11. **Что будет, если сохранить в JPEG и снова открыть?** JPEG сжимает с потерями: края станут чуть размытыми, и заливка может сработать неидеально. BMP хранит пиксели как есть.
12. **Можно ли было сделать иначе?** Да. Можно хранить список фигур и перерисовывать их (векторный подход), но тогда сложнее карандаш и заливка. Холст можно сделать на `Panel`, но у `Panel` свойство `DoubleBuffered` защищённое (`protected`), и пришлось бы писать класс-наследник.

## 8. Теория, которую нужно знать

### 8.1. `Bitmap` и `Graphics`

`Bitmap` — картинка в памяти, прямоугольник пикселей. `Graphics` — «кисть художника», у неё есть методы `DrawLine`, `DrawRectangle`, `DrawEllipse`, `FillRectangle`, `DrawImage`, `Clear`. Чтобы рисовать на картинке, для неё создают `Graphics`:

```csharp
using (Graphics g = Graphics.FromImage(bmp))
    g.DrawLine(pen, lastPoint, e.Location);
```

`Graphics` в обработчике `Paint` (`e.Graphics`) рисует не в картинку, а на сам элемент управления.

### 8.2. `Pen`, `Brush`, `Color`

`Pen` (перо) задаёт цвет и толщину линии: `new Pen(lineColor, 5)`. `LineCap.Round` скругляет концы, чтобы штрих карандаша из многих коротких отрезков выглядел гладко. `Brush` (кисть) заливает фигуры: `new SolidBrush(backgroundColor)` — кисть одного цвета (ей ластик и «Вырезать» закрашивают области фоном); `Brushes.White` — готовая белая кисть, её не нужно освобождать. `Color.ToArgb()` превращает цвет в одно число `int` (альфа, красный, зелёный, синий). Числа удобно сравнивать в заливке.

### 8.3. События мыши

`MouseDown` — кнопку нажали, `MouseMove` — мышь двигается (приходит и без нажатой кнопки — так рамка ластика следует за курсором), `MouseUp` — кнопку отпустили, `MouseLeave` — мышь ушла с элемента. `Cursor.Position` — положение мыши на экране, `canvas.PointToClient(...)` переводит его в координаты холста. `e.Location` — координаты мыши относительно элемента. Холст стоит в левом верхнем углу панели и совпадает по размеру с картинкой (`SizeMode` по умолчанию `Normal`), поэтому координаты мыши совпадают с координатами пикселей `bmp`. `e.Button` показывает, какая кнопка нажата: правая здесь игнорируется. `Control.ModifierKeys` — зажатые Shift/Ctrl/Alt.

### 8.4. Событие `Paint` и `Invalidate()`

Windows сама решает, когда элемент надо перерисовать, и вызывает `Paint`. `Invalidate()` говорит: «этот элемент устарел, перерисуй». Сразу он ничего не рисует, а ставит запрос в очередь. Правило WinForms: всё видимое рисуется только в `Paint`.

### 8.5. Двойная буферизация

Без неё каждая команда рисования сразу попадает на экран, и глаз видит промежуточные состояния: мерцание. С ней всё рисуется в невидимый буфер в памяти и затем одним блоком копируется на экран. В WinForms её включают стилем `ControlStyles.OptimizedDoubleBuffer` (свойство `DoubleBuffered`). У `PictureBox` он включён по умолчанию.

### 8.6. `MenuStrip`, `ToolStrip`, горячие клавиши

`MenuStrip` — главное меню, пункты имеют тип `ToolStripMenuItem`. У пункта есть свойство `ShortcutKeys` (например, `Keys.Control | Keys.Z`), и форма сама вызовет его `Click` по нажатию клавиш. `ToolStrip` — панель инструментов, на ней лежат `ToolStripButton`, `ToolStripLabel`, `ToolStripComboBox`, `ToolStripSeparator`. Свойство `Checked` у кнопки показывает её «нажатой».

### 8.7. Стандартные диалоги

`ColorDialog`, `OpenFileDialog`, `SaveFileDialog`. `ShowDialog()` возвращает `DialogResult.OK`, если пользователь нажал ОК. Выбор хранится в свойствах `Color` или `FileName`. `Filter` задаёт типы файлов строкой вида `"BMP (*.bmp)|*.bmp|JPEG (*.jpg)|*.jpg;*.jpeg"`: пары «подпись|маска» через `|`.

### 8.8. Форматы BMP и JPEG

BMP хранит пиксели без сжатия: файл большой, качество не теряется. JPEG сжимает с потерями: файл маленький, но цвета слегка искажаются. Формат при сохранении задаётся явно: `bmp.Save(path, ImageFormat.Jpeg)`. Загрузка формат определяет сама: `Image.FromFile(path)`.

### 8.9. Стек `Stack<T>`

Коллекция «последним пришёл — первым ушёл». `Push` кладёт наверх, `Pop` снимает верхний элемент, `Count` — количество. Для Undo это естественно: отменяется последнее действие. В заливке стек хранит пиксели, которые ещё надо проверить.

### 8.10. Буфер обмена `Clipboard`

Системный буфер обмена Windows, общий для всех программ. `Clipboard.SetImage(bitmap)` кладёт картинку, `Clipboard.ContainsImage()` проверяет, есть ли там картинка, `Clipboard.GetImage()` достаёт её. Работает только в STA-потоке, поэтому в `Program.Main` стоит атрибут `[STAThread]`.

### 8.11. `Rectangle`

Прямоугольник: `X`, `Y`, `Width`, `Height`. `Rectangle.Empty` — все нули. `Rectangle.Intersect(a, b)` возвращает общую часть двух прямоугольников: так выделение обрезается по картинке. `bmp.Clone(rect, format)` вырезает из картинки кусок-копию.

### 8.12. `LockBits` и `Marshal.Copy`

`LockBits` «закрепляет» пиксели картинки в памяти и возвращает адрес первого (`data.Scan0`). `Marshal.Copy` копирует байты между этой неуправляемой памятью и обычным массивом C#. Для формата 32bppArgb один пиксель — один `int`, а пиксель (x, y) лежит в массиве под индексом `y * width + x`. После работы обязательно вызывается `UnlockBits`.

### 8.13. `using` и `IDisposable`

`using (var x = ...) { ... }` вызывает `x.Dispose()` при выходе из блока, даже если случилось исключение. Объекты GDI+ (`Graphics`, `Pen`, `Bitmap`, `Image`) держат ресурсы Windows, и их нужно освобождать.

### 8.14. `partial class` и Designer

`Form1` разделён на два файла: `Form1.Designer.cs` (создание контролов в `InitializeComponent()`) и `Form1.cs` (наш код). Компилятор собирает их в один класс. Строка `this.canvas.MouseDown += new MouseEventHandler(this.canvas_MouseDown);` в Designer подписывает наш метод на событие.
